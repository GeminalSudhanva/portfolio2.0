trend2stock
1. Frontend
Core Framework: Next.js (v16.2.6) with React (v19)
Language: TypeScript
Styling: Tailwind CSS (v4.0) via PostCSS
Icons: Lucide React
Authentication & Client Services: Firebase Client SDK (v12.14.0) for user management and authentication
Date & Time Utilities: Day.js
Hosting/Deployment: Typically deployed on Vercel (configured to point to https://trend2stocks.vercel.app)
2. Backend
Web Framework: FastAPI (Python 3.11) served via Uvicorn
AI & Multi-Agent Orchestration: LangGraph and LangChain (specifically utilizing langchain-openai and langchain-community) to coordinate a multi-agent system comprising:
Discovery Agent: Scans news/RSS feeds for viral trends.
Sentiment Agent: Assesses the social/public sentiment.
Extraction Agent: Isolates key trends and phrases.
Mapping Agent: Maps trending topics to relevant stock symbols.
Analysis Agent: Synthesizes final insights.
LLM Engine: Multi-provider support configured via environment variables:
Groq (llama-3.3-70b-versatile) — used in production.
OpenAI (gpt-4o-mini)
Ollama (qwen2.5:3b) — for local testing and development.
Financial & Market Data: Yahoo Finance API (yfinance)
Task Scheduler: APScheduler (Advanced Python Scheduler) for running routine background background jobs to scrape and analyze trends.
Auth & Server Admin: Firebase Admin SDK for server-side token validation and secure actions.
Hosting/Deployment: Deployed on Render (as a Python web service).
3. Database
Production Database: PostgreSQL (hosted on Neon DB using psycopg2-binary and SSL connections).
Local Development Database: SQLite (trend2stock.db).
Database ORM: SQLAlchemy (v2.0+) for database operations and schema migration.

eco tracker
1. Database Layer
Primary Database: Supabase (PostgreSQL)
A shared cloud PostgreSQL instance accessed directly by the web frontend, mobile application, and backend API.
Supabase Realtime API is utilized in both the web admin dashboard and the mobile app to sync new reports and status updates instantly.
Key tables:
reports: Stores citizen-reported complaints (e.g., resource type, location, severity, status, and metadata).
profiles / user_profiles: Manages user profiles, role-based controls (admin vs. citizen), and communication preferences (phone, language, location).
Fallback Databases (Configured in Backend):
PostgreSQL (pg pool): Direct relational connection fallback.
MongoDB (mongoose): Document-based database fallback.
In-Memory Storage: Fallback storage used when no external database is connected.
2. Back-End Layer
The backend is a lightweight Node.js/Express service that processes incoming webhooks, logs reports, and communicates with telephony services.

Language & Runtime: Node.js (CommonJS)
Web Framework: Express.js (express)
Key Integrations:
Exotel IVR API/Webhooks: Handles incoming citizen telephony calls and parses IVR menu keypresses (DTMF inputs) to log complaints about water, power, or waste.
Twilio API: Triggers automated outbound phone calls (using Twilio XML/Alice voice synthesis) to citizens when an administrator resolves a reported issue.
Core Packages: cors, dotenv, axios, @supabase/supabase-js, pg, mongoose
Key Files:


server.js (Backend Entry)


package.json (Backend Config)
